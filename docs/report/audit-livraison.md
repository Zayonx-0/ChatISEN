# Recette de la livraison ChatISEN du 23 novembre 2026

**Décision : J1 refusé, J2 incomplet, J3 sans preuves suffisantes.** La démo locale permet de créer un compte, d’écrire un message dans un groupe et de le relire. Le profil prévu pour le jury présente trois blocages indépendants : confidentialité du temps réel, persistance des données et appels audio/vidéo.

**Révision examinée.** Le dépôt local est sur `main` au commit `a3241a92f4efe2781213914df29794e2513d1a23`, un commit après le tag `v0.1.0`. Le paquet racine annonce `0.1.0` et OpenAPI annonce `1.0.0` pour le contrat. Aucun tag applicatif `v1.0.0` ni distant Git configuré dans cette copie. Les deux copies du [cahier d’architecture](../../ARCHITECTURE-ChatISEN.md) sont identiques au moment de l’examen.

## Résultats obtenus pendant l’audit

| Vérification | Résultat et portée |
|---|---|
| `npm run verify` | Réussi. Le seul parcours appelle directement l’API standalone, inscrit une personne, crée un groupe, poste et relit un message. Le test transmet le cookie à la main. Il n’exerce ni deuxième navigateur ni WebSocket. Le script racine de « typecheck » vérifie seulement que quatre fichiers ont du contenu. |
| `node --test tests/contract/contract.test.mjs` | 8/8 réussis avec une base PostgreSQL **16.15** jetable et le pilote `pg`, dont deux passages du runner de migration. Le SQL seul a également été appliqué deux fois avec succès. La suite valide les exemples et le schéma. La cible de déploiement spécifie PostgreSQL **17**. |
| Compilation réelle des workspaces | Le build Vite du client réussit. Le build TypeScript de l’API échoue sur le type du mode d’appel et les déclarations WebSocket. Le contrôle TypeScript du client échoue notamment sur les déclarations React et React DOM. Les erreurs de types sont confirmées avec Node 24.14.1 sur une copie du commit. |
| Configuration Compose | La lecture YAML échoue à la ligne 32 sur la valeur de `LIVEKIT_KEYS`. Le poste dispose aussi d’un client Docker sans sous-commande Compose accessible ni socket de daemon disponible. La pile complète n’a pas démarré. |
| Requêtes adressées à Fastify sous Node 24 | Par injection HTTP dans le JavaScript émis par TypeScript : inscription de test `201`, lecture anonyme du profil effectif `/api/auth/me` → `401`, route contractuelle `/api/v1/me` → `404`, `/readyz` → `200` avec `memory-fallback`. |
| `npm run study` | Le programme rend `blocked` faute d’export `getStats`, avec un code de sortie nul. Même avec un CSV, le chemin livré calcule une perte moyenne. Il manque l’entraînement, la comparaison avec la règle de référence et le jeu de test séparé par appel. |

## Écarts et conditions de réception

| Priorité et exigences | Constat sur la livraison | Preuve attendue pour lever la réserve |
|---|---|---|
| **Critique · confidentialité** (S01–S03) | Dans les deux serveurs, l’inscription à un canal WebSocket ne vérifie ni session ni appartenance. La diffusion ne revalide pas les droits après retrait ou déconnexion. Constat sur le code. [Fastify](../../apps/api/src/server.ts#L46) · [Standalone](../../apps/standalone/server.mjs#L9) | Deux membres reçoivent le message privé. Un tiers, un ancien membre et une session révoquée ne reçoivent aucun nouvel événement. |
| **Bloquant · installation et API** (O01, D01) | YAML Compose invalide, compilation de l’API en échec et divergence de routes et de formats HTTP/WS avec le contrat publié. Le serveur applique ses contrôles manuellement. Les cibles Make `core` et `full` appellent le même test. [Compose](../../infra/compose/docker-compose.yml#L32) · [Makefile](../../Makefile) · [Contrat](../../packages/contracts/schemas/openapi.json) | Un clone neuf compile les deux workspaces, démarre la pile et passe des assertions de contrat adressées à l’API réellement servie. |
| **Bloquant · identité et messagerie durables** (F01–F05, O04–O06) | Le serveur cible utilise des collections en mémoire pour les comptes, sessions, messages et pièces jointes. La classe PostgreSQL contient une sonde SQL. Les écritures métier et la diffusion interprocessus n’y sont pas raccordées. Standalone utilise un fichier JSON. Le cookie préfixé `__Host-` est émis sans attribut `Secure` dans le profil local livré, autre écart que le test HTTP manuel ne détecte pas. [Stockage](../../apps/api/src/store.ts) · [Session](../../apps/api/src/server.ts#L24) | Une connexion depuis un vrai navigateur, un historique retrouvé après redémarrage, deux réplicas concordants et lecture refusée après révocation. |
| **Bloquant · audio et vidéo** (F06–F08, F10–F12, S03) | L’API gère une invitation et retourne un jeton de démo. Le client React affiche un emplacement pour la vidéo. Il manque la connexion de la salle aux SDK LiveKit, la publication/réception des pistes et l’admission signée. [Appels](../../apps/api/src/server.ts#L38) · [Interface](../../apps/web/src/main.tsx#L5) | Deux navigateurs échangent du son dans les deux sens et décodent de la vidéo, puis essai conférence, partage d’écran, retrait et relais TURN. |
| **Fonctionnel · groupes, fichiers et ergonomie** (F02–F05, F09, F13) | Les opérations de groupe sont partielles. Le client React attend les membres dans l’objet conversation alors que la création les renvoie à côté. La route multipart conserve le contenu en mémoire et l’interface n’offre pas d’envoi de fichier. Sous 800 px la liste des conversations est masquée sans navigation de remplacement. [Client](../../apps/web/src/main.tsx) · [API](../../apps/api/src/server.ts#L31) | Depuis le navigateur : créer un direct, gérer le groupe, envoyer et retélécharger un fichier identique en appel et ouvrir un autre fil à 390 px. |
| **Exploitation et évaluation** (S04–S05, O02–O08, P01–P04, A01–A03, D02–D03) | Deux panneaux Grafana et une collecte Prometheus de l’API sont livrés. Nginx écoute en HTTP. OpenTofu ne définit aucune ressource, Ansible s’arrête avant la livraison, la sauvegarde est décrite en prose. Le dépôt ne contient ni pipeline GitHub Actions, ni scénario k6/Playwright, ni règles Alertmanager. Les mesures et la répétition de soutenance restent à établir. [Infra](../../infra/tofu/main.tf) · [Sauvegarde](../../ops/backup/README.md) · [Étude](../../analysis/study.py) | Déploiement HTTPS reproductible, alerte reçue, sauvegarde restaurée, résultats de charge et d’étude reliés au commit, puis démonstration complète chronométrée. |

**Ordre de reprise.** Fermer l’accès indu aux événements privés. Rendre ensuite le profil cible compilable et démarrable, raccorder les routes contractuelles à PostgreSQL et connecter le client au serveur média. La prochaine décision J1 doit être prise sur un scénario à deux navigateurs : conversation privée, redémarrage avec historique intact, appel audio puis vidéo avec réception distante.
